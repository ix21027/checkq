# CheckQ

Веб-застосунок для проходження тестів (Vue 2 + Vuetify + Vuex). Підтримує формули (KaTeX) та банк питань.

**Працює повністю на фронтенді, без бекенду** — дані питань і вся серверна логіка перенесені всередину застосунку (раніше фронтенд звертався до окремого Rails API).

## Вимоги

- **Node.js** (перевірено на Node 24; має працювати і на 14–18)
- npm

## Встановлення

```bash
npm install
```

## Запуск (режим розробки)

```bash
npm run serve
```

Потім відкрий **http://localhost:8080**

> Скрипти `serve` і `build` уже містять `NODE_OPTIONS=--openssl-legacy-provider`.
> Це потрібно для сумісності старого webpack (Vue CLI 3) із сучасним Node — без цього
> збірка падає з помилкою `ERR_OSSL_EVP_UNSUPPORTED`.

## Збірка (production)

```bash
npm run build
```

Готові статичні файли з'являться в каталозі `dist/` — їх можна віддати будь-яким
статичним сервером.

## Лінтинг

```bash
npm run lint
```

## Як це працює без бекенду

Оригінально фронтенд звертався до Rails API (`checkq-api`). Тут той самий API
реалізовано локально, з тими самими формами відповідей:

| Файл | Призначення |
|------|-------------|
| `src/fetchapi/data.json` | Перенесені дані: 9 предметів, 508 питань, 2032 відповіді |
| `src/fetchapi/localApi.js` | Логіка ендпоінтів: список предметів, генерація тесту, перевірка відповідей, банк питань, реєстрація/логін |
| `src/fetchapi/index.js` | `http` із тим самим інтерфейсом, що раніше axios, але звертається до локальної логіки |

Завдяки цьому Vuex-стори (`src/store/modules/*`) не змінювалися.

Деталі:
- Правильна відповідь — **перша** у списку відповідей кожного питання.
- Генерація тесту розподіляє обрану кількість питань між обраними предметами.
- Реєстрація та вхід зберігаються локально у браузері (`localStorage`) — окремого
  сервера для користувачів немає.
